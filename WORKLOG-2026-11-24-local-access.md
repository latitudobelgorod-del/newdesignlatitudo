# Локальная копия: доступ, права Windows, запуск (24.11.2026)

Задача была — проверить доступы и продолжить работу в этом чате (до этого проект вёл
Codex/ChatGPT). Правок в коде сайта не было. Ничего не коммитилось и не выкладывалось.

## Что было сломано

1. **Права Windows на папку проекта.** Песочница не могла выдать доступ на запись:
   у папки `C:\OSPanel\home\newdesign-latitudo` не хватало права менять владельца.
   Команды падали до запуска: `windows-acl workspace grant failed`.
2. **Уровень целостности на вложенных папках.** После починки п.1 писать можно было
   только в корень проекта; в `local`, `tools`, `docs`, `.git` — «Отказано в доступе».
   Причина не в списке разрешений, а в метке целостности Windows: у корня она была
   снижена, у старого содержимого — нет. Проверено на `tools`: после снижения метки
   запись заработала.
3. **MySQL-5.7 не был запущен.** Apache и PHP-8.2 работали, порт 3306 пуст — сайт
   отдавал 500 на всех страницах.

## Что сделано

- Права: штатным скриптом диагностики добавлен полный доступ учётной записи `Irina`
  на папку проекта. Откат: `C:\OSPanel\home\dsh-acl-recovery\acl-backup-*.ps1`.
- Разрешения и метка целостности разосланы по дереву проекта:
  `icacls <корень> /grant "<SID>:(OI)(CI)F" /T` и `icacls <корень> /setintegritylevel (OI)(CI)Low /T`.
  Обработано 441 334 объекта; 20 087 не поддались — принадлежат служебным учётным
  записям (`CodexSandboxOffline`) и группе «Администраторы».
- MySQL-5.7 запущен штатным конфигом (`modules\MySQL-5.7\my.ini`, `127.0.1.26:3306`).
  Запускать нужно с полным доступом: под песочницей он не может писать в свою папку данных.
- В `.git/config` этой копии добавлено `http.sslBackend=openssl`: системный TLS
  на машине не работает (`schannel: SEC_E_NO_CREDENTIALS`), без этого git по HTTPS падает.

## Проверки

Локальный сайт `http://newdesign-latitudo.local/` — все страницы HTTP 200, PHP-ошибок
в HTML нет: главная (обычный шаблон и `?newdesign=Y`), каталог, карточка товара,
корзина, `/bitrix/admin/`. Стили и скрипты редизайна отдаются (HTTP 200).

Git: `fetch` обычной командой проходит; `commit` и `push` проверены на одноразовой
ветке `_dsh-push-check` — коммит создан, ветка появилась на сервере, затем удалена
и на сервере, и локально.

## Ограничения

- `docs/` принадлежит `CodexSandboxOffline`: из консоли агента туда писать нельзя,
  файловые инструменты работают. Лечится только сменой владельца с правами администратора.
- `bitrix/cache` принадлежит «Администраторам» — консольно кэш не снести.
- `push` из консоли агента требует токена в заголовке: хелпер `gh auth git-credential`
  вызывается через `sh`, а подпроцессы `sh` песочница блокирует. Рабочая команда:

  ```powershell
  $tok = (& 'C:\Program Files\GitHub CLI\gh.exe' auth token).Trim()
  $b64 = [Convert]::ToBase64String([Text.Encoding]::ASCII.GetBytes("x-access-token:$tok"))
  git -c credential.helper= -c "http.https://github.com/.extraheader=Authorization: Basic $b64" push origin <ветка>
  ```

  В обычном терминале (вне песочницы) `git push` работает как всегда.
- После перезагрузки MySQL снова нужно поднимать (обычно это делает OSPanel).
