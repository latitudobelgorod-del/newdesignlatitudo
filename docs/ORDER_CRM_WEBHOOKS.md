# Корзина и быстрый заказ: лиды Битрикс24

Состояние: выложено и проверено 20.11.2026 по разрешению пользователя на latitudo.ru, поддоменах easydecking.ru и latitudo.org.

## Что подключено и где видеть лид

Подключён действующий обработчик `aspro:oneclickbuy.next`, включая быстрый заказ из корзины. Другие способы создания заказов сами по себе в очередь не включаются.
В админке: **Магазин → Заказы → открыть заказ**. В карточке просмотра/редактирования выводится блок «Отправка заказа в Битрикс24»: статус и после подтверждения **«Лид #…»** со ссылкой. Это карточка заказа магазина, а не результаты веб-форм.
Новые заказы сохраняются на сайте и отправляются штатной очередью независимо от доступности CRM. Почтовая часть действующего обработчика сохранена. Статусы: ожидает, отправляется, отправлено, ошибка, результат уточняется, CRM отключена для дилерского региона. После обработки обновить страницу карточки.
Для старого заказа без записи очереди выводится отсутствие подтверждённой связи. Это не утверждение, что лида нет. Старые заказы автоматически не переотправляются; для привязки сначала найти и подтвердить конкретный лид. Заказ ИЗИ 1649 не переотправляли.

## Дилеры ИЗИ

Условие относится **только к дилерским регионам**: REGION_FOR_DILER заполнено и REGION_MY пусто → лид не создаётся. У недилерских регионов пустое REGION_MY не мешает отправке. Неизвестный регион/отсутствующее свойство блокируют отправку до проверки. Исходный регион и разрешение сохраняются при заказе, перед отправкой свойства перечитываются. Уже пропущенные заявки после смены флага автоматически не отправляются.
Настройка: Контент → Региональность (aspro.next) → Регионы → город → «Город». Почта дилера — отдельное свойство REGION_DILER_EMAIL; пустой адрес оставляет получателя существующего почтового шаблона. Очередь не изменяет эти адреса.

## Очередь и защита от дублей

Таблица `b_site_order_crm`: order_id, status, lead_id, attempts, last_error, payload_json, context_json, updated_at. Агент `SiteOrderCrm::runQueue();`, интервал 60 секунд, до трёх заказов за запуск.
Отправка выполняется из сохранённого пакета исходного заказа. Повторное enqueue того же ID не перезаписывает пакет. Уникальная пара в CRM: ORIGINATOR_ID=`latitudo.ru:order`, `easydecking.ru:order` или `latitudo.org:order`, ORIGIN_ID=числовой ID заказа. Это отдельные пространства от веб-форм и от других сайтов.
Перед созданием выполняется поиск этой пары. Блокировка MySQL исключает параллельную отправку. ID лида сохраняется в очереди. При потере ответа или сбое после начала отправки допускается только поиск существующего лида: повторное создание запрещено, даже если лид пока не найден. При явной ошибке CRM разработчик исправляет причину и повторяет через `SiteOrderCrm::delivery()->send(ID)` в авторизованном CLI-контексте; публичной кнопки обхода проверок нет.
Ошибка записи очереди журналируется по номеру заказа. Автоматического восстановления таких записей по данным текущей админки нет: нужно восстановить исходные данные и исключить существующий лид.

## Конфигурация и откат

`local/php_interface/include/order-crm/config.php` содержит домен, проверенный корень, пользователя, имя секретного файла и признак дилерских правил; самого секрета в Git нет. RU/ORG используют существующий `~/.latitudo_b24.php`, ИЗИ — `~/.easydecking_forms_b24.php`. Портал только latitudo.bitrix24.ru. TLS проверяется, таймаут HTTP ограничен.
Подключение идёт через `local/init.php`; не создавать заменяющий ядро `local/php_interface/init.php`.
Опция `sale/site_order_crm_enabled=Y` включает новую очередь и отключает прежний прямой REST-вызов в обработчике. **При выключении этой опции новые заказы снова пойдут по прежней ветке обработчика.** Поэтому выключение не является способом полностью запретить CRM. На ИЗИ прежняя ветка ссылается на отсутствующий старый секретный файл. Откат проводить разработчиком: проверить незавершённые состояния, сохранить очередь и ID, согласовать режим новых заказов; при возврате файлов использовать только проверенные копии. Не переигрывать старые заказы и не удалять очередь вслепую.
CLI `tools/order-crm/migrate.php check` проверяет доступ чтения CRM; `enable` выполняет резервное копирование схемы/затронутых строк b_option, b_agent и существующей очереди, создаёт очередь, сохраняет границу старых заказов и включает последней опцию. Повторное включение требует проверки состояния.

## Почтовые уведомления заказов — изменение 20.11.2026

ACTIVE=N проверено после изменения. Отключение относится ко всем получателям этих шаблонов, включая покупателей и скрытые копии нового заказа.

Отсутствие прямого вызова Mail/Send в тесте НЕ означает отсутствия писем: штатные события магазина имеют побочные эффекты. Ранее указанная граница проверки уточняется этим результатом. Больше не создавать реальные технические заказы под существующим пользователем без проверки подавления почтовых событий и других автоматизаций.

Где увидеть настройки: Настройки → Настройки продукта → Почтовые события → Почтовые шаблоны; найти ID 29, 40, 41, 55 (неактивны) и 54 (активен).
