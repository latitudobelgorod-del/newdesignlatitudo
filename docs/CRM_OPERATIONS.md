## Ежедневная работа

1. **Веб-формы:** Сервисы → Веб-формы → Результаты → нужная форма. Колонка «Отправлено в CRM» содержит статус и, после подтверждения, ссылку «Лид #…».
2. **Быстрый заказ / корзина:** Магазин → Заказы → открыть заказ → блок «Отправка заказа в Битрикс24». Заказы находятся в магазине, а не в результатах веб-форм.
3. Нажать ссылку на лид для перехода в latitudo.bitrix24.ru. Нужны права доступа к лиду.
4. Если заявка только что поступила, обновить страницу после запуска очереди. Интервал агента — 60 секунд, до трёх записей за запуск; задержка может быть больше минуты.

Заявка сначала сохраняется на сайте. Почта работает отдельным существующим механизмом. Очередь передаёт данные через REST-вебхук и сохраняет полученный ID лида. Статус «Отправлено» подтверждает получение ID от CRM, но не доставку письма и не окончательного ответственного после автоматизации CRM.

## Настройка вкладки CRM

**Сервисы → Веб-формы → Настройка форм → нужная форма → CRM.** Здесь задаётся сопоставление: какое поле формы передать в какое поле CRM. Действующая интеграция читает связи из базы сайта. Проверенный снимок для разработчика — `tools/form-crm/mappings.json`.

Старый способ отправки должен оставаться **«вручную» (M)**. Реальную автоматическую отправку выполняет наша REST-очередь. Не переключать старую интеграцию на «автоматически»: это не включает новый вебхук и может задействовать старый импорт с ошибкой OTP.

Связи во вкладке CRM управляют веб-формами. Поля заказов задаются отдельно обработчиком заказа; изменение вкладки CRM формы их не меняет.

## Ответственный

Начальный ответственный — **Дмитрий Ошкин, ID 65**. Для одного существующего лида менять «Ответственного» в карточке Битрикс24. Это не меняет будущие заявки.

Для будущих заявок разработчик меняет `ASSIGNED_BY_ID`:

- Веб-формы: `local/php_interface/include/latitudo_form_crm_delivery.php`, метод `send()`.
- Заказы: `local/php_interface/include/order-crm/OrderDelivery.php`, метод `send()`. Согласованно обновить формируемый пакет и резервную ветку обработчика oneclickbuy.next, чтобы не осталось старого ID.

Обновить подсказки, тесты и документацию, проверить активность сотрудника, затем выложить с резервной копией и проверить контрольную заявку. ID сотрудника CRM не равен ID пользователя админки сайта. Уже созданные лиды не переназначаются. Изменение кода может затронуть ещё не отправленную очередь. Владелец вебхука и ответственный — разные роли.

После создания CRM может изменить ответственного своими роботами или бизнес-процессами. Проверять историю лида. Правила распределения в CRM этой интеграцией не менялись; их изменение — отдельная согласованная задача.

## Статусы и ошибки

| Статус | Что делать |
|---|---|
| Ожидает | Дождаться запуска очереди, обновить страницу. При длительном ожидании проверить агент / cron. |
| Отправляется | Дождаться завершения попытки. Не создавать заявку повторно. |
| Отправлено + ссылка | Лид подтверждён. Открыть карточку. |
| Ошибка | Сохранить ID заявки и текст ошибки, передать разработчику. После устранения причины выполнить контролируемый повтор. |
| Результат уточняется | Ответ мог потеряться после создания лида. Система ищет существующий лид; не создавать второй вручную вслепую. |
| Нет подтверждённой связи / старый зелёный значок | Историческая запись без ID в новой очереди. Это не доказательство отсутствия лида. |

У веб-форм после исправления явной ошибки можно использовать штатное действие «Отправить в CRM»: оно перехватывается REST-обработчиком. Для заказов публичной кнопки повтора нет; разработчик проверяет состояние очереди и выполняет допустимый повтор через служебный код. Подтверждённые отправки не создаются заново. После неоднозначного ответа разрешён поиск существующего лида, а не повторный add.

Старые результаты и заказы автоматически не переносятся. Перед ручной отправкой старой заявки обязательно проверить CRM, чтобы не создать дубль. Старый заказ ИЗИ №1649 не переотправлялся; подтверждённая ссылка не найдена. Лид №211937 относится к другому заказу на kazan.latitudo.ru.

## Если создаётся новая форма

Новая форма и копия существующей **не подключаются к REST автоматически**.

1. Определить назначение: только почта или почта + CRM; согласовать получателей и поля.
2. Создать форму, вопросы, почтовый шаблон и вызов формы на сайте. Заполнить русское название в блоке «Меню результатов в административном разделе», чтобы форма появилась в меню результатов; проверить права доступа.
3. Для CRM настроить связи полей; старый sender оставить ручным.
4. Разработчик добавляет ID в список FORMS, сверяет и сохраняет mappings.json, проверяет поддерживаемые типы полей, расширяет тесты. На ИЗИ проверить региональные правила.
5. После согласованной выкладки и резервной копии включить новую форму миграцией, зафиксировать границу старых результатов.
6. Проверить сохранение результата, письмо, создание ровно одного лида, поля, начального ответственного, статус и ссылку. Обновить инструкции.

Если нужна только почта, REST не включать. Настройка CRM сама по себе не включает нашу очередь.

## Для разработчика и восстановление

Заказы подключены через действующий `aspro:oneclickbuy.next`, включая быстрый заказ из корзины. Другие способы создания заказа этим автоматически не охватываются.
Таблица заказов — b_site_order_crm; агент — SiteOrderCrm::runQueue(); конфигурация — local/php_interface/include/order-crm/config.php. Подключение — local/init.php; не создавать заменяющий ядро local/php_interface/init.php.
Выключение sale/site_order_crm_enabled возвращает новые заказы в прежнюю ветку кода, а не полностью запрещает CRM. Не использовать эту опцию как общий выключатель отправки. Откат и повтор — по [инструкции заказов](ORDER_CRM_WEBHOOKS.md), с сохранением очереди и ID лидов.
Секрет вебхука хранится вне публичного каталога; не публиковать его в документах, Git или переписке. Перед изменением сверить сайт, пользователя, путь и текущие хэши, сохранить проверенную копию файлов и затронутых данных вне www. Не восстанавливать всю базу ради одной настройки.
