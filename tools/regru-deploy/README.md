# Выкладка latitudo.ru через GitHub Actions

Выкладка запускается вручную из ветки `main`. Сначала согласуйте план правки, затем получите явное разрешение на выкладку проверенного изменения.

## Однократная настройка

- В GitHub настройте окружение `production` с разрешением на выкладку из `main`.
- Создайте отдельный SSH-ключ для GitHub Actions. Публичный ключ добавьте в `~/.ssh/authorized_keys` пользователя `u0916578` на REG.RU. Приватный ключ добавьте в секрет окружения `REG_RU_DEPLOY_KEY`.
- Поместите в секрет `REG_RU_KNOWN_HOSTS` запись OpenSSH для `vip125.hosting.reg.ru` на порту 22. Сверьте отпечаток ключа хоста с данными REG.RU или через уже доверенное подключение. При смене ключа хоста обновите запись после новой сверки.
- На хостинге требуется команда `python3` и права пользователя на нужные файлы в `~/www/latitudo.ru/local`.

## Как выложить правку

1. В **Actions → Deploy latitudo.ru → Run workflow** выберите `main` и `plan`. Введите полные SHA текущей версии файлов на проде (`base`) и версии, которую собираетесь выложить (`target)). Оба коммита должны быть в истории `main`.
2. Сверьте список файлов в шаге **List changed production files** с одобренной правкой. Режим `plan` строит список по Git без подключения к хостингу.
3. После разрешения на выкладку запустите `deploy` с теми же SHA. Скрипт проверит файлы на проде перед записью. При расхождении с `base` выясните, как появились изменения, и отразите версию продакшена в Git по правилам проекта.
4. Проверьте страницы, затронутые правкой, и при необходимости очистите кеш соответствующего компонента Битрикса. Workflow проверяет HTTP-ответ главной страницы. Запишите SHA выложенной версии и ссылку на запуск.

Выкладка работает с обычными файлами под `local/`. Замены отдельных файлов атомарны. Если операция прервётся жёстким завершением процесса или связь оборвётся во время записи, сверяйте фактические версии на сервере перед повторным запуском. Не меняйте те же файлы вручную, пока идёт выкладка.

## Как откатить правку

После разрешения на откат запустите `plan`, поменяв местами SHA `base` и `target`. Сверьте список и запустите `deploy` с этими значениями. Проверьте затронутые страницы.
