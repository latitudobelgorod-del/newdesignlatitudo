# TOORDER → REST Битрикс24

Подготовлено 19.11.2026. **Не включено на проде.** Только форма ID 1 (`TOORDER`, «Товар под заказ»).
Другие формы и корзина используют прежние маршруты. Отдельный коммит корзины `b02de38`
с заменой ответственного на 65 пока также не выложен.

## Поведение

- После сохранения результата событие `onAfterResultAdd` добавляет запись в очередь.
  Почтовые шаблоны и отправка письма не изменяются. REST выполняется агентом, а не в запросе посетителя.
- Агент обрабатывает до трёх заявок за запуск. Интервал 60 секунд; фактическая задержка зависит
  от планировщика агентов Битрикса. Первый запуск после переключения — не раньше 120 секунд.
- Сохраняются все 15 существующих связей из `b_form_crm_field`, включая прежнее назначение
  `COMMENTS` и пользовательских полей. Телефон и email преобразуются в REST-массивы.
- Ответственный новых лидов — 65. Портал строго `latitudo.bitrix24.ru`.
  Ключ читается из прежнего файла `~/.latitudo_b24.php`, не попадает в Git/интерфейс/логи.
- Подтверждённый ID сохраняется в `b_latitudo_form_crm`, затем ставится штатный `SENT_TO_CRM=Y`.
  В списке результатов: текстовый статус, ссылка на лид либо ошибка. Ошибки экранируются.
- Действие «Отправить в CRM» для формы 1 использует новый обработчик с проверкой сессии,
  доступа к форме и результату. Другие формы обрабатывает ядро как прежде.
- Повторный вызов с сохранённым ID не создаёт лид. Перед созданием выполняется поиск по
  `ORIGINATOR_ID=latitudo.ru:webform`, `ORIGIN_ID=1:<ID результата>`; параллельные запросы
  исключаются MySQL `GET_LOCK` для конкретного результата.
- Если ответ на создание потерян или процесс оборвался, состояние `uncertain`/`sending`
  разрешает только поиск уже созданного лида. **Автоматического повторного создания нет**,
  даже если поиск пока пуст. Менеджер проверяет CRM; это сознательное ограничение, поскольку
  REST `crm.lead.add` не гарантирует идемпотентность при потере ответа.
- Обычная явно возвращённая CRM-ошибка допускает повтор через штатное действие после исправления.
  Ранее отправленные прежним подключением заявки (`SENT_TO_CRM=Y`) не пересылаются.
  Исторические заявки автоматически не импортируются.

## Остановка / откат

`php tools/form-crm/migrate.php disable` сначала сохраняет снимок, выключает REST и убирает
агента. Очередь, ID лидов, результаты и связи сохраняются. Письма и сохранение форм продолжают
работать. Старое OTP-подключение остаётся ручным: автоматически включать его при неизвестном
исходе отправок небезопасно. Уже запущенный обработчик может закончить текущую операцию;
перед дальнейшими изменениями проверить `sending`/`uncertain` и созданные лиды.

При необходимости вернуть исходный режим подключения — отдельно проверить очередь и
восстановить только соответствующую строку `b_form_crm_link` из JSON-копии. Не импортировать
весь снимок поверх новых данных и не удалять таблицу очереди. Код откатывается из Git после
остановки агента. Опции и данные новых лидов не теряются при откате файлов.
