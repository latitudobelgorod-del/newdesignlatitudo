## Отправка и статусы

После сохранения результата создаётся запись b_latitudo_form_crm. Агент
LatitudoFormCrm::runQueue(); выполняет до трёх заявок за запуск; интервал 60 секунд,
фактическая задержка зависит от cron. Сетевых запросов CRM при отправке формы посетителем нет.

Связи полей сохранены полностью; проверенный снимок — mappings.json. Старый sender
переведён в M (ручной), но REST работает автоматически. Административная кнопка
«Отправить в CRM» для включённых форм использует REST с проверкой прав/сессии.
После подтверждения ID лида сохраняется, затем выставляется штатный SENT_TO_CRM=Y.
Список показывает текст состояния, ошибку либо ссылку на лид; ошибки экранируются.

Начальный ASSIGNED_BY_ID=65 (Дмитрий Ошкин). **Это не конечный ответственный**:
в контрольных лидах 217893–217903 существующая автоматизация CRM поменяла его
на «РОП Москва», ID2475. История 217893 подтверждает «Дмитрий Ошкин → РОП Москва».
Правила распределения не менялись. У контрольного TOORDER217891 остался65.

Идемпотентность: блокировка GET_LOCK на результат, поиск точной пары
ORIGINATOR_ID=latitudo.ru:webform / ORIGIN_ID=<форма>:<результат>, сохранение состояния
sending до запроса, сохранение lead_id до штатного флага. Повтор с известным ID
не создаёт лид. После timeout/неизвестного ответа — только поиск; слепой повтор add
запрещён. Явная ошибка допускает ручной повтор после исправления. Исторические
результаты автоматически не отправляются; на включении сохраняется отдельная граница каждой формы.

Файл CLAIM передаётся в crm.lead.add как множественное fileData. Копия существующего
обработчика overrides/claim_file_crm.php развёрнута в bitrix/php_interface/include/claim_file_crm.php:
почтовое вложение сохраняется, старый агент не дублирует REST-загрузку.
Агент PDF калькулятора использует сохранённый ID лида для REST-заявок, старый поиск
оставлен для исторических результатов. Генерация PDF и почтовые вложения не менялись.

## Включение и откат

CLI: php tools/form-crm/migrate.php check|enable|disable <ID формы>.
Изменения разрешены скриптом только на /var/www/u0916578/data/www/latitudo.ru, user u0916578.
Перед включением сверяются SID/CRM и все связи из mappings.json. Структура/затронутые
строки настроек сохраняются и проверяются вне www. Флаг включается последним.

Сервер vip125.hosting.reg.ru (SSH latitudo-ru). Бэкапы настроек:
/var/www/u0916578/data/codex-backups/form<ID>-rest-enable-20261119-*.json.
Исходники перед расширением: /var/www/u0916578/data/codex-backups/forms-rest-20261119-extend/*.before.

Откат: сначала disable нужной формы, проверить sending/uncertain, затем восстановить
её файлы/настройки из проверенной копии. Общие файлы откатывать только после отключения
всех затронутых форм. disable сохраняет результаты/ID/очередь, оставляет legacy ручным;
агент удаляется только когда выключены все формы. Не включать старую OTP-интеграцию
автоматически и не восстанавливать весь снимок поверх новых заявок.

Секрет ~/.latitudo_b24.php вне www/Git; новый транспорт проверяет HTTPS/сертификат/хост.
Modern Web Guidance применён: доступные текстовые статусы, обычные ссылки, alt="" у дублирующих значков.
