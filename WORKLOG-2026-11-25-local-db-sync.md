# Локаль приведена к состоянию прода (25.11.2026)

Задача: на latitudo.ru уже выложен новый дизайн и актуальный контент, в git код свежий,
а локальная копия показывала старый дизайн. Нужно было привести локаль к проду.

## Диагностика: дело было в базе, не в коде

| | Прод | Локаль (до) |
|---|---|---|
| Шаблон по умолчанию | `aspro_next_newdesign`, условие пустое | тот же шаблон, но условие `?newdesign=Y` |
| Товаров (`b_iblock_element`) | 7 920 | 7 237 |
| Заказов (`b_sale_order`) | 1 649 | 1 582 |
| Последнее изменение каталога | 24.11, 04:00 | 23.11, 12:10 |

Код сверил по SHA-256, 9 708 файлов `local/`: из 1 428 отличавшихся **1 416 отличаются
только переводами строк** (CRLF на Windows против LF на сервере — грабли из WORKFLOW,
раздел 7). Реально разное — 12 файлов: 6 незакоммиченных локальных правок и несколько
файлов, которые на проде **старее** git (`home_form_newdesign.php`, `Input_icons.svg`,
`oneclickbuy.next/script.php`). Код не трогал.

## Что сделано

1. Дамп локальной базы сохранён как точка отката: `outputs/db-backup-local-20261124.sql` (395 МБ).
2. На проде запущен существующий `~/lc-transfer/dump.sh` (`mysqldump --single-transaction
   --quick`, без блокировок таблиц). Результат: `~/lc-transfer/db.sql.gz`, 64 МБ.
3. Дамп скачан одним потоком в `outputs/db-prod-20261124.sql.gz`.
4. Развёрнута база `latitudo_ru_prod` (utf8 / utf8_unicode_ci, как на проде), импорт 427 МБ.
   Старая база `latitudo_ru` **не тронута** — остаётся для отката.
5. Пользователю `latitudo_ru` выдан доступ к новой базе (`GRANT ALL ON latitudo_ru_prod.*`).
6. В `bitrix/.settings.php` база переключена на `latitudo_ru_prod`.
7. Снесён кэш Битрикса: `bitrix/cache`, `managed_cache`, `stack_cache`.

### Процедура в конце дампа

Импорт основного тела прошёл полностью (1 058 таблиц). Упал только хвост с процедурами:
`mysqldump` вставляет туда `ALTER DATABASE \`u0916578_lat\`` — на локальной машине такой
базы нет. Хвост вырезан в отдельный файл, имя базы заменено, процедура создана:
`clear_b_sale_fuser` в базе есть. В самом конце осталась безвредная ошибка
`Variable 'time_zone' can't be set to the value of 'NULL'` — из-за отсутствия
начальных `SET` из шапки дампа; на данные и процедуру не влияет.

## Откат

Вернуть в `bitrix/.settings.php` значение `'database' => 'latitudo_ru'` — старая база
на месте и не изменялась. Дополнительно есть дамп `outputs/db-backup-local-20261124.sql`.

## Ограничения и что осталось

- После импорта локальная база — копия прода: локальные тестовые данные и правки контента
  из локальной админки заменены боевыми.
- 1 416 файлов в `local/` имеют CRLF вместо LF. На работу не влияет, но шумит в сравнениях
  с сервером. Лечится `git checkout -- .` по WORKFLOW, раздел 7; не делал, потому что это
  затронет рабочую копию с незакоммиченными правками.
- MySQL-5.7 после перезагрузки компьютера нужно поднимать снова (обычно это делает OSPanel).

## Сверка «прод — эталон» (25.11)

Пользователь указал: то, что сейчас на проде, должно быть и в git, и на локали.
Сверены все 9 735 файлов `local/` на сервере.

- Файлов, которые есть на проде и отсутствуют в git, больше нет. Дозагружены 8 картинок
  (`images/newdesign/vacancies/`, `images/newdesign/company/`): они были на сервере, но
  ни в git, ни локально.
- **Спрайт `Input_icons.svg`.** На сервере лежат две версии: `Input_icons.svg` (604 байта)
  и `input_icons.svg` (481 байт). CSS ссылается только на вариант с заглавной «I»
  (10 ссылок), на строчный — ноль. В git был строчный, то есть при выкладке на Linux
  спрайт галочек фильтра мог отдать 404. В git файл переименован в `Input_icons.svg`
  с прод-содержимым, неиспользуемый строчный дубль убран (на Windows они неразличимы).
- **Незакоммиченная фича** «группы распродажи» (6 файлов: `promo_products.php`,
  `newdesign-catalog.js/css`, `nd-sale-list.css`, `news_newdesign/template.php`,
  новый `promo_groups.php`) сохранена в ветке `wip/sale-groups-20261124`, коммит 3cf69ec.
  На проде её нет, поэтому рабочая копия возвращена к прод-состоянию.
- Коммиты в рабочей ветке: 65ba9ef (документация), 198c81f (спрайт и картинки).

### Прод отстаёт от git

Два файла на сервере старее репозитория, оба правились мимо деплоя:

| Файл | В git | На проде |
|---|---|---|
| `home_form_newdesign.php` | `z-index:100000` — окно заявки поверх cookie-баннера (коммит 7 окт, 11:08) | `z-index:10070` — версия от 11:04, то есть до правки |
| `oneclickbuy.next/script.php` | без лишних пробелов | лишние пробелы в комментарии (косметика) |

Первый — содержательная правка: без неё на проде окно заявки на главной уходит под
cookie-баннер. Нужна выкладка из git, требует отдельного разрешения на прод.
